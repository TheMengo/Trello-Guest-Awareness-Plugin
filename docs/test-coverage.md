# Test coverage and acceptance boundaries

This document maps the requested scenarios to implemented test assertions. It is a coverage inventory, not a statement that a particular test run passed. See [test-report.md](test-report.md) for recorded commands, outcomes, and environment details.

Unit tests run the classification, preference, API, and service-worker logic independently of Trello's UI. Browser tests load the production MV3 extension into Chromium, display the local Trello-like HTML fixture under a mocked `https://trello.com` route, and supply deterministic responses through the test worker's fetch fixture. The production source does not contain the mock transport. Browser fixtures do not establish live Trello acceptance.

## Additional security and privacy checks

- `classify.test.ts`: **ordinary draft text is neither persisted nor fingerprinted** verifies that changing ordinary comment text does not change the stored warning fingerprint and that sensitive words are absent from it.
- `api.test.ts`: **API reference and credential validation rejects arbitrary routes and header injection** and **loads board members and Workspace members through documented GET routes without cookies or URL secrets** verify the request boundary.
- `background.test.ts`: **service worker RPC keeps credentials private and restricts senders and mutations** contains subtests for trusted-only storage access, sender restrictions, credential-free preference replies, setup-only authorization checks, validated preference writes, safe broadcasts, and the unconfigured settings flow.
- Browser: **Settings setup validates credentials, requests only read authorization, verifies access and disconnects** checks invalid-key handling, the authorization URL's read-only scope and default `never` expiry, the `/members/me` verification request, clearing the token input, connected-tab updates, and disconnect behavior. Four expiration scenarios additionally check all four choices, URL parameters, persistence/reopening, invalid storage recovery, and unchanged existing-token verification. Pure authorization/preferences tests cover validation and storage independence.
- Browser fixture teardown checks the captured page/worker console errors and test-transport violations. The worker fixture validates read-only methods, the authorization header, omitted cookies, rejected redirects, allowed routes, and absence of URL credentials. The API unit test also verifies the redirect-rejection option. No test intentionally posts a real Trello comment.

## Accessibility checks and remaining manual acceptance

The browser accessibility scenario checks an actual modal `dialog`, an accessible name reference, a description reference, initial focus on Cancel, the full forward Tab cycle, reverse focus wrapping, Escape cancellation, unchanged draft contents, focus returning to the original editor, and a dialog fitting a 390-pixel viewport. It also checks computed dark-theme indicator/dialog background colors. Other browser scenarios produce desktop/light, narrow/dark, and settings screenshots for visual inspection. Settings use explicit form labels, a live status region, visible focus styles, and native controls.

These checks are deliberately narrower than a complete accessibility certification. Actual screen-reader announcements, reading order with assistive technology, operating-system high-contrast modes, browser zoom, and a comprehensive color-contrast audit require manual acceptance. Screenshot existence alone is not evidence of visual approval; recorded inspection belongs in the test report.

Live Trello compatibility, delivery of Trello notifications, undocumented or changed comment editors, Edge-specific behavior, and Web Store installation have not been established by this fixture suite. Before broad internal rollout, an authorized reviewer should smoke-test designated cards and test accounts using the documented installation and acceptance steps. Existing company-board comments must not be used as test posts without explicit authorization.

## Authorization verification regressions (1.0.1)

The extended suite additionally covers native WorkerGlobalScope.fetch receiver semantics (old build fails before any native request), fresh repeated authorization checks, HTTP 400/401 classification, internal versus transport/timeout/JSON failures, current-storage credential selection before storage events, blank-token reuse of replacements, removed-token prevention, changed-key mismatch, worker RPC failure after saving, and removal during pending verification. See [the authorization report](authorization-fix.md) for evidence and exact lifecycle. No live token is used.

## Modern card DOM and live validation (1.0.2)

Eight new browser scenarios reproduce the actual inspected `#overlay-contents` root, hidden legacy dialog, collapsed/ProseMirror editor, no-form Save, username mention components, and comment-container layout. They cover assigned, prior unassigned, draft, board-only, internal/similar/plain/code/URL/malformed mentions, Cancel, Ctrl/Command+Enter, double-click single submission, and card navigation. Pure structured resolver tests require matching exact marker/label/identifier and reject ambiguous people. The current Chrome test card also passed non-posting live smoke tests documented in [card-warning-fix.md](card-warning-fix.md); no live comments or memberships were changed.
