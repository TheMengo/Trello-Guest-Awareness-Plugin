# Troubleshooting

Version 1.0.2 fixes the current Trello card dialog, editor, and username-based rendered mention components. If board warnings work but card warnings do not, update the currently loaded extension folder, click its Reload button at `chrome://extensions`, and refresh Trello. The live-verified selectors and remaining acceptance tests are in [Card warning fix](card-warning-fix.md). Historical plain text alone is never treated as a verified mention.

For the fixed pre-network Illegal invocation defect and version 1.0.1 reload steps, see [Authorization verification fix](authorization-fix.md). Save & verify issues a fresh request in the extension service worker; inspect that worker’s Network panel rather than the Settings page’s Network panel. Internal worker and transport errors have different messages.

- **Unable to verify guest status:** open extension Settings. Enter a valid Trello developer API key and a read-authorized token, then Save & verify. The authorized account must be able to read the current board and its Workspace’s complete member list. Expired/revoked tokens require authorization again. Missing Workspace data, empty/ambiguous membership lists, and API errors are never displayed as “No guests.”
- **No indicator:** verify awareness is enabled, the extension has permission to run on Trello, and this is a normal `https://trello.com/b/...` or `/c/...` route. Reload the tab after installation/reloading. Verified guest-free boards intentionally have no indicator. A changed Trello header/card DOM may provide no safe insertion point; report the DOM adapter issue without sharing sensitive card contents.
- **Guest changes seem delayed:** wait 60–90 seconds on a visible tab, switch back to the tab, or use Refresh. Manual refresh still caches for at least 30 seconds to reduce requests across tabs. HTTP 429 pauses requests for at least 60 seconds or the server’s Retry-After (bounded to one hour).
- **No confirmation:** a matching board/card dismissal may exist; restore it in Settings. Board and card confirmations are independent. Unknown editors, stale/failed/loading membership data, retired SPA editors, and unsupported submission shortcuts preserve native commenting. Read the limitations document before company rollout.
- **Post Anyway leaves the draft:** the native control may have changed, been disabled, or rejected a synthetic click. Draft text is untouched. First verify there is no newly posted comment in Trello; avoid repeatedly clicking while Trello is processing. Close the card/reopen it or refresh, validate on a test card, and disable awareness in Settings if this UI variant is incompatible. Never troubleshoot by posting sensitive real content.
- **Extension reloaded/updated:** reload all existing Trello tabs so a fresh content script is registered. Stored warning preferences and authorization persist. Clearing all dismissals does not remove credentials.
- **Settings cannot save:** reload the extension Settings page and check browser policy/storage restrictions. The service-worker console is available from `chrome://extensions` → extension → service worker. Diagnostics should not include credentials or comment bodies.
- **Developer browser tests cannot launch:** run `npx playwright install chromium`. Use unbranded Chromium for command-line extension loading. Platform sandbox policies may require allowing local browser execution. Do not use your everyday browser profile; tests create temporary profiles. `PLAYWRIGHT_CHROMIUM_EXECUTABLE` can select an existing compatible Chromium binary.

For a live smoke test, use a designated authorized board with test employees/guest accounts and clearly disposable cards. Verify board set difference, native click/keyboard continuation, cancel/draft preservation, one comment after double click, membership changes, and settings restoration. Non-posting live smoke checks were performed as described in the card fix report; live posting and membership-change acceptance remain outstanding.
