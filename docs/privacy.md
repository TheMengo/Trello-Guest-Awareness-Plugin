# Privacy and security

The extension is an awareness tool. It has no backend, telemetry, analytics, or advertising. It never changes a board, card, comment, membership, permission, or mention through the Trello API.

The only API host permission is `https://api.trello.com/*`; only the fixed documented read-only GET routes in `src/api.ts` are used. The content script runs on `https://trello.com/*`. The sole named Chrome permission is `storage`. There are no cookies, browsing-history, debugger, scripting, webRequest, clipboard, or account-email permissions. The service worker is necessary for authorized cross-origin requests and keeping credentials away from content scripts.

The API key and user-authorized Trello token are stored in this browser’s `chrome.storage.local`, limited to trusted extension contexts with `setAccessLevel`. Local extension storage is not encrypted by the extension. Tokens appear only in the Authorization header sent to `api.trello.com`, never API query URLs or diagnostics. The optional authorization link sends the public API key to `trello.com` and requests only read access with the selected expiration: 1 hour, 1 day, 30 days, or Never expires (the default). `never` has no scheduled expiration, but access can still be revoked or invalidated. The stored selection affects only newly issued tokens; existing tokens retain their original expiration. Every employee authorizes their own private token; tokens must not be shared. No application secret is included or required. No token extraction, private endpoints, or cookie/session access occurs.

Minimal board/Workspace/card membership is cached in service-worker memory (64 endpoint entries, 60-second ordinary TTL, 30-second minimum for refresh). Persisted data consists of credentials, the authorization-expiration preference, enabled status, separate dismissal fingerprints with stable IDs/timestamps, and SHA-256 membership digests used to detect observed changes. Dismissal fingerprints contain guest identities and signal categories but no comment bodies, titles, or hashes of draft text. No board titles, attachments, comment history bodies, or emails are requested or retained.

Draft text is read only transiently in the isolated content script for local mention detection and unchanged-draft checks during confirmation. It is never sent to the worker, saved, logged, or transmitted. Historical mentions are inspected only in visible supported mention markup with a verified member ID or an exact username whose component marker and label agree with current membership; comment history bodies are not fetched. Native Trello submission is still Trello’s own existing workflow.

The extension keeps no user activity log. Network errors use fixed messages rather than server response bodies. Published automated fixtures and screenshots use fictional identities and comments. Private live acceptance evidence can contain real account identities and card activity; it is excluded from the repository and distribution packages. Removing saved credentials does not revoke the Trello token; revoke it at Trello separately. Removing the extension clears its local extension storage according to browser behavior.
