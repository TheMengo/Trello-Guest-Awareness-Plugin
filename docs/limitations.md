# Verified scope and limitations

1. **Live smoke testing has a defined scope.** Version 1.0.2 was inspected and smoke-tested on the designated authenticated test card. Assigned/history/draft warnings, native Save/Command+Enter confirmation, Cancel/draft preservation, and card-close cleanup worked; five original comments remained unchanged. Live Post Anyway posting, double-click submission, and historical-only involvement without assignment were not exercised by modifying the live card. Those scenarios pass the automated fixtures. See [live evidence and remaining acceptance](card-warning-fix.md).
2. **No documented pre-submit hook.** Trello documents its commenting workflow and mentions, but no supported Chrome-extension pre-comment interception API or stable DOM contract. `src/dom.ts` explicitly lists recognized selectors. Save clicks, native comment-form submits, and Ctrl/Command+Enter in those recognized editors are covered. Plain Enter remains a newline. Other editors, mobile applications, Inbox, undocumented shortcuts, shadow/iframe editors, and controls with different selectors may not be intercepted. Unsupported card controls display a limitation when a supported card root is visible. A wholly unrecognized page layout may also lack a safe insertion point.
3. **Native replay is verified on fixtures.** Post Anyway invokes the existing Save control’s `.click()` once or the captured native form’s `requestSubmit()`. The tests cover ordinary and deferred native form submission. This does not prove that a particular live Trello React handler accepts an untrusted programmatic click. If a live variant ignores it, the untouched draft remains. Use a designated test card to verify before rollout; Settings can disable awareness or restore/change dismissals to keep native commenting available. The extension never replaces an editor, reassigns text, synthesizes a Trello API comment request, or patches fetch/XHR.
4. **Warning-only, fail-open behavior.** If data is loading, older than two minutes, failed, or unavailable, the extension leaves commenting usable and shows an unverifiable state where it can. It cannot guarantee a pre-submit warning in those conditions. After loading/reloading the extension, reload Trello tabs. Existing orphaned content scripts may show an unable-to-verify message until page refresh.
5. **SPA DOM reuse.** Navigation retires the previous known editor. If Trello reuses that exact DOM editor across cards rather than replacing it, pre-submit confirmation stays unavailable for it until the page/editor is recreated. This avoids applying the new card’s audience to an old editor. Supported fixture navigation replaces editors and resumes normal warnings.
6. **Eventual membership updates.** API cache is 60 seconds; manual/focus refresh uses a 30-second floor. Visible tabs refresh approximately every 60–90 seconds. Hidden tabs recheck on focus. Rate limits and failures delay this further. Changes that occur and fully revert between observations cannot be detected. Dismissal changes propagate across observed tabs. Persisted observed membership digests prevent old dismissals from resurrecting after observed remove/re-add changes.
7. **Mention scope.** Draft detection resolves complete current usernames and explicit member-ID chips. It conservatively ignores code, URLs and email-like text. Formatting/escaping, renamed usernames, pasted literal `@username`, and UI-specific transformations can make actual Trello notifications differ; messages say “may notify.” Earlier comments contribute only when visible supported legacy stable-ID components or modern username components resolve to an exact verified current member. Modern component identifier, marker, label, and person type must agree; plain historical text is ignored. Hidden/paginated history and plain historical `@text` are not analyzed. A historical mention alone says nothing about future notifications.
8. **Access is broader than notifications.** Membership and mentions identify potential audiences, not guaranteed delivery or exhaustive watchers. Guests can watch cards without being assigned. Workspace guests are not necessarily external employees. Public-board viewers, shared links, Workspace non-board viewers, deactivated/invited members, and other access pathways are not an exhaustive access audit.
9. **Read access is required.** A 403 or unavailable Workspace membership does not mean no guests. Some organization policies or account permissions may prevent verification. The extension uses the still-documented API-key/token authorization flow. OAuth2/backend infrastructure is not required for this local version. Users must renew/revoke tokens themselves.
10. **Browser scope.** Automated extension tests use downloaded unbranded Chromium on macOS; the current authenticated Chrome page was separately smoke-tested. Chrome installation is documented; Edge uses the same MV3 APIs but has not been separately tested. Unpacked installation may be restricted by company browser policy. No Web Store publication, enterprise deployment, or signing was performed.
